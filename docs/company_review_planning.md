# 风险发现 Agent：公司画像与审查规划

本模块在专业分析之前运行，只形成公司事实和待查问题，不提前认定风险。

## 处理过程

1. 程序加载基础检查目录，按行业、主营业务、收入模式、客户与渠道、供应链、核心资产、发展阶段、经营地区检索招股书。
2. 各主题均衡取回命中原文及相邻上下文。标题仅用于定位，不随机抽取全文；每轮原文总量默认不超过 24,000 字符。
3. 模型提取中性画像事实，每条必须引用实际提供的切片和原文摘录。程序核对切片编号与摘录；该检查保证引用可定位，不等同于自动证明模型概括完全正确。
4. 信息不足或冲突时，最多提出 4 个问题并补读一轮。没有找到的字段显示未知，冲突事实保留，不自行猜测。
5. 根据画像提出最多 12 项专项检查，分派给财务、法律、业务或市场 Agent。基础检查始终保留；专项检查可由人工确认调整。
6. 专业 Agent 根据检查问题独立检索全文中的支持证据和反证。画像引用只是提出问题的依据，不直接充当风险成立的证据。

风险发现页显示公司画像、引用、未知字段、基础检查与专项问题。查询、命中切片编号、检索方式、模型版本、提示词快照和分派任务写入分析审计记录。此模块是程序编排工作流，不是模型自主调用的工具。

## 向量服务暂不可用

`configs/base.yaml` 当前设置：

```yaml
retrieval:
  mode: bm25
agents:
  discovery_strategy: company_review_plan
  profile_context_chars: 24000
```

`bm25` 模式不发起向量化请求，也不连接向量库。画像、专业核验与财务事实提取使用 BM25，财务提取保留字段锚点辅助。BM25 是词法检索，不具备向量检索的同义表达召回能力。

向量服务恢复后，可将 `retrieval.mode` 改为 `hybrid`。新发现流程仍然保留，检索增加语义通道；语义检索失败时回退到 BM25。专业 Agent 的检索问题优先用于 BM25，确实没有命中时才使用基础查询兜底。

修改配置后重启后端；新流程对重新启动的分析生效，不重写历史结果。

## 兼容与验证

`discovery_strategy: legacy_risk_discovery` 保留旧流程，供对比或回退。新模块与旧流程不在同一次分析中重复执行。

单元测试覆盖引用校验、未知字段、一次补读、基础检查保留、无向量检索、专业全文查证和失败降级。离线测试使用模拟模型，不能替代真实招股书与真实模型的效果评估。
