## 数据治理规则

1. `data/raw` 中的文件不重命名内容、不覆盖、不手工修改。
2. 每次解析均记录源文件哈希，证据通过哈希、页码和坐标回链。
3. `data/interim` 和 `artifacts` 可由流水线重建，不作为事实来源。
4. 模型训练只读取 `data/processed`，禁止直接从报告或上市后材料取特征。
5. 测试样本必须是可公开或已脱敏的小文件，官方数据不进入Git。

每家公司在三个类型目录中使用完全相同的子目录名，例如：

```text
data/raw/prospectus/03696_英矽智能/
data/raw/company_info/03696_英矽智能/
data/raw/market/03696_英矽智能/
```

`company_info/<公司目录>/公司信息.json` 是三类原始文件的关联入口。每家公司在 `raw` 主数据区只保留两个 JSON：公司信息和日线行情；供应商快照及交叉核验材料进入 `data/interim/audit`。

所有PDF和结构化数据均先登记到 `data/app.db`。PDF解析、向量和截图路径必须包含
稳定的 `document_id`，禁止只按公司目录写出，以免多份资料互相覆盖。详细操作见
`docs/资料登记与版本管理.md`。
