# 资料登记与版本管理

项目使用“原始文件按数据类型/公司保存，SQLite统一登记，派生产物按文档版本隔离”
的方式支持多家公司、多份招股书和其他数据。

## 增加一家公司

三个标准目录必须使用完全相同的公司文件夹名：

```text
data/raw/prospectus/<股票代码_公司名称>/
data/raw/company_info/<股票代码_公司名称>/
data/raw/market/<股票代码_公司名称>/
```

其中 `company_info/<公司目录>/公司信息.json` 是唯一结构化入口。放入资料后执行：

```powershell
conda activate hk-ipo-risk
python scripts/register_company_data.py `
  --company-folder "<股票代码_公司名称>" `
  --project-root "D:\东吴证券"
```

批量登记全部公司：

```powershell
python scripts/register_company_data.py --all --project-root "D:\东吴证券"
```

命令可以重复运行。相同哈希生成相同ID，不会产生重复记录；发现未登记文件时会输出
“待处理”提示。

## 增加第二份招股书或其他公告

把原始PDF放进对应公司的目录，并在 `公司信息.json` 的 `documents` 中增加一项：

```json
{
  "documents": {
    "prospectus_main": {
      "document_type": "prospectus",
      "local_file": "data/raw/prospectus/03696_英矽智能/招股章程_2025-12-18_繁体中文.pdf",
      "document_date": "2025-12-18",
      "available_at_date": "2025-12-18",
      "language": "zh-Hant",
      "source_kind": "official_hkex_public_filing",
      "source_url": "港交所原始URL",
      "file_size_bytes": 28848316,
      "sha256": "64位小写SHA-256",
      "page_count": 672,
      "text_layer_status": "present"
    },
    "prospectus_supplement": {
      "document_type": "prospectus",
      "local_file": "data/raw/prospectus/03696_英矽智能/补充招股章程_2025-12-22_繁体中文.pdf",
      "document_date": "2025-12-22",
      "available_at_date": "2025-12-22",
      "language": "zh-Hant",
      "sha256": "另一份文件的SHA-256"
    }
  }
}
```

映射键必须唯一，但 `document_type` 可以相同。系统会为每个文件生成不同
`document_id`，页面、切片、向量、截图和报告不会互相覆盖。

常用 `document_type`：

- `prospectus`：正式或补充招股书；
- `allotment_results`：配发结果；
- `listing_announcement`：上市公告；
- `financial_report`：财务报告；
- `legal_filing`：法务或监管文件；
- `industry_report`：行业材料。

系统允许新增其他小写下划线类型，不需要修改枚举代码。

## 增加其他结构化数据

标准 `data/raw/market/<公司目录>/日线行情.json` 会被自动识别。其他数据在
`公司信息.json` 的 `datasets` 中声明：

```json
{
  "datasets": {
    "pre_listing_market_snapshot": {
      "dataset_type": "pre_listing_market",
      "title": "上市前恒生指数与新股市场快照",
      "local_file": "data/raw/external/03696_英矽智能/上市前市场快照.json",
      "sha256": "64位小写SHA-256",
      "available_at": "2025-12-29",
      "file_format": "json",
      "period_start": "2025-11-01",
      "period_end": "2025-12-29",
      "row_count": 40,
      "usage_scope": "pre_listing_market_features",
      "pre_listing_eligible": true
    }
  }
}
```

上市后行情必须设置 `pre_listing_eligible=false`。预测模块只能选择
`available_at <= as_of_date` 且允许上市前使用的数据。

## 文档产物与SQLite分工

```text
原始PDF/JSON
    ↓ 计算SHA-256并登记
data/app.db
    ↓ 按company_id、document_id、available_at选择
pages.jsonl / chunks.jsonl / embeddings.npy / 证据截图
    ↓
RiskFinding、AgentTrace、人工复核、Prediction继续写回data/app.db
```

SQLite保存资料关系和运行状态；1024维向量保存在文档级 `embeddings.npy` 中，
`vector_indexes` 表只登记模型、维度、数量、哈希和文件路径。

## 不可违反的规则

1. 不覆盖已登记的原始文件；新版本使用新文件名。
2. `available_at` 表示系统实际能够看到资料的日期，不能用事后日期倒填。
3. PDF哈希与资料清单不一致时停止导入。
4. 上市后行情只用于标签和回测，不得进入上市前预测特征。
5. 证据必须保留 `document_id`、源哈希、物理页码和坐标。
