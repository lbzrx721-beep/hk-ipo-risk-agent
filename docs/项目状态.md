# 项目状态（截至 2026-07-26）

本文件用于回答三个问题：目前已经完成什么、未来还需要什么、下一步先做什么。准确率与
召回率必须在比赛数据和人工金标准到位后实测，当前不提前宣称达到赛题阈值。

## 已完成

### 数据与证据底座

- 已建立公司、文档版本、来源哈希、分析运行、证据、风险、Agent轨迹和人工审计的SQLite目录。
- 可解析带文字层或需OCR兜底的招股书PDF，保留物理页码、印刷页码、原文坐标和页面截图。
- 已接入结构化表格证据链：有边框表格使用PyMuPDF网格解析，无边框财务表按文字坐标恢复
  多层“期间/年份/单位”表头、行列和单元格坐标；同一页面的多个表格会按行距分段。
- 表格同时保存 `tables.jsonl` 规范化工件和表格专用检索切片。切片重复表头并包含Markdown、
  逐行语义、币种、期间和单元格引用，与普通文本共同向量化并写入Chroma；专业Agent和
  决策Agent可明确识别 `source_kind=table`。
- 表格证据的确定性核验不再用生成后的Markdown硬匹配PDF全文，而是逐个复核所引单元格值
  是否存在于原表坐标内，并保留整表高亮截图。
- 文档切片和向量索引按 `document_id/embedding_model` 隔离并缓存，可重复分析而不重复向量化。
- 网页分析优先使用内存向量，随后把同一份预计算向量异步写入Chroma；后台失败不影响报告，
  并以 `building/ready/failed` 状态记录。
- Chroma已升级至1.5.9并使用独立的 `data/vector_store_v1`；当前写入按集合串行化并使用
  v3物理集合隔离旧HNSW段和旧切片结构。原PDF、文本切片和预计算向量均保留，可无模型调用地重建。
- 网页支持拖入单份招股书，并自动识别股票代码、公司名称和招股书日期，识别结果允许校正。

### Agent风险分析

- 12类风险按职责分配给财务、法务、业务和市场Agent，覆盖现金消耗、客户/供应商集中、
  关联交易、赎回/对赌、诉讼处罚、牌照依赖、单一产品依赖等风险。
- 每个专业Agent通过 `qwen3-embedding:4b` 混合索引寻找其负责风险的候选原文；四个角色
  使用独立ARK客户端并行，每个角色一次Kimi批量调用完成证据约束核验。
- 风险发现Agent通过ARK调用 `deepseek-v4-flash`，在不接收固定目录主题的前提下按
  70,000字符章节包双路并行阅读；模型只能引用当前章节包真实 `chunk_id`。章节包完成后进行
  全文级语义合并，标题不同但实质相同的风险可
  合并，每条原始候选都必须留下唯一映射。
- 人工确认前已移除固定8条上限，不再静默截断不同风险；语义合并失败时保留全部候选并使用
  精确标题兜底。部分批次失败追加固定目录时，已被动态风险覆盖的目录项不会重复加入。
- 开放风险不会直接进入报告，而是按财务、法律、业务或市场职责重新分派，经过语义检索和
  专业Agent批量核验后才可生成候选结论。`needs_more_evidence` 是本轮结束后的证据不足状态，
  页面转为待人工核验，不再错误显示为持续补证。
- 专业核验使用支持、需补证、证据不足、主体或期间错配、重复合并和冲突六类状态。机器不能
  最终驳回；未支持风险保留在提案账本与轨迹中。
- 固定查询、BM25和硬锚点不是主分析路径，只在搜索规划、向量服务或模型节点失败时兜底。
- 搜索规划、证据分析和最终裁决均支持指数退避重试；JSON格式、风险覆盖和证据白名单错误
  也会触发重试，并把具体校验错误反馈给下一次生成，不再原样盲重试。
- 全文发现使用“首轮完整发现 + 一次条件式遗漏补扫”：只有模型明确仍存在证据独立的重大
  遗漏时才补扫，且不得换标题重复同一事实。单章节包最多返回40条候选，请求上限只限制
  单次载荷，不限制风险总数。大量候选按角色和容量分区语义合并。
- 向量召回默认使用16组公司特异检索问题、语义与关键词混合命中、相邻上下文及48个章节
  覆盖锚点，最多选择520个高召回原文切片；四个原文包并发处理，以兼顾召回和等待时间。
- 财务、法律、业务和市场Agent分别加载独立专业章程，搜索和证据核验不再只靠一个角色枚举
  区分。画像节点只给范围建议，人工确认前保留全部候选，优先保障证据召回。
- 模型工具调用保存提示词版本、SHA-256、完整快照和纠错记录，提示词、输入约束、输出和
  证据来源可以逐次追踪。
- 生效提示词已升级为详细版：风险发现使用动态主题与系统化阅读视角，专业核验逐项检查主体、
  期间、表格口径、条款和反证，四套角色章程明确跨角色边界，决策Agent统一校准结论、
  严重程度、置信度和未决事项；阅读视角不作为固定风险清单。
- 四路汇合后使用决策Agent：全部有原文证据的专业提案按批交给裁决模型复核结论边界、
  严重程度与不确定性，并实时输出结构化决策卡片。模型失败或建议不采纳时不会静默删除
  已支持风险，而是确定性保留并记录冲突，交给人工最终确认。
- 多角色核心编排已使用LangGraph：财务、法律、业务和市场Agent并行执行，决策Agent在四路
  分支汇合后运行；图节点、执行模式和完成角色写入根AgentTrace。
- 单公司模型调用数、输入/输出Token和人民币估算费用继续审计；默认硬门限均为关闭状态，
  长文档不会因累计输出Token较多而暂停。
- 有充分证据的风险数低于期望值时不再让整家公司失败；系统保存零/少结论报告和完整候选
  提案账本，并明确给出覆盖提醒，便于检查漏证原因。
- PDF每页会本地检测图片对象、表格网格、无边框文本列和流程图几何候选；文字层表格已进入
  结构化语义链。视觉模型接口继续作为扫描表格、复杂合并单元格和流程图的后续兜底，不会
  默认把所有页面发送给视觉模型。
- LangGraph在全文发现和公司适用性判断后设置人工确认门；确认前专业Agent不启动，确认后按
  人工修改后的范围继续四路并行分析。
- 所有风险结论必须引用实际候选 `chunk_id`；无证据时不生成正式风险结论。

### 赛事真实数据接入

- 已核验并接入2020—2025年565份赛事招股书，全部PDF可打开、无加密，共354,497页。
- 已流式接入4,117,539条港股日行情，不把1GB级CSV整体载入内存；生成按公司拆分的官方
  日行情、公司清单、时间切分及首日/5日/20日/60日收益、破发、显著下跌和回撤标签。
- 训练/验证/测试固定按2020—2023年、2024年、2025年进行时间切分；上市后行情明确禁止
  进入上市前预测特征。
- 已识别赛事证券基本信息文件在256KiB处截断，不能作为正式证券主表；上市日期从招股书后
  首条行情恢复，发行价优先使用正式上市价、缺失时使用上市首日昨收价代理，并逐行记录来源。
- 555家公司具备完整60个交易日行情；未产生行情的撤回上市或特殊证券样本单独标记，
  不作为普通缺失值静默填充。

### Point-in-Time预测基线

- 已将招股书发布日期固定为预测时点，为554家有完整五日标签的公司生成34个上市前特征。
  每个特征均有 `available_at` 和 `source_ref`，自动拒绝晚于预测时点的输入。
- 已从1.1GB全市场行情生成每日市场情绪缓存，提取预测日前5/20/60日的收益、上涨比例、
  波动、振幅、成交趋势和活跃证券数；公司自己的上市后行情和发行价代理不进入特征。
- 已生成只使用当时已观察完成样本的近期IPO环境特征，目标公司及尚未到观察日的历史IPO
  标签会被自动排除。
- 已训练招股书结构、市场环境和融合三组逻辑回归消融基线，输出模型、逐公司概率、阈值、
  PR-AUC、Brier、校准分箱、Top-20%指标和线性贡献解释。
- 阈值只在2024验证集选择并限制“全部报风险”；预处理和模型仅用2020—2023训练集拟合。
  三组模型均未通过业务质量门禁，融合模型验证PR-AUC为0.3089，低于0.3425正例基准率。
  当前产物是诚实的研究基线，不能宣称已获得有效预警能力。

### 历史招股书Agent特征实验

- 已实现可恢复的历史招股书批量实验队列：样本按训练/验证数据量比例分配，并只使用文档哈希
  排序，不读取五日涨跌标签进行挑选。
- 每家公司依次执行PDF解析、Ollama `qwen3-embedding:4b` 向量化、DeepSeek全文动态发现、
  四专业Agent并行核验和决策裁决；状态、流式事件、失败原因和产物均逐公司落盘。
- 已实现与风险主题无关的通用Agent特征，包括风险与证据数量、严重程度、角色分布、置信度、
  OCR比例、计算与不确定性、Agent轨迹及失败工具调用；固定目录风险保留类型特征。
- 动态风险使用 `open_*` 运行ID，不能直接作为跨公司模型列。当前先保留通用统计，待训练集
  样本积累后使用风险标题和结论的向量聚类学习可解释主题，不提前规定公司风险主题。
- 单公司真实冒烟已成功：保誠122页招股书用时258秒，得到17条风险、19条证据、7条Agent
  轨迹和82次成功工具调用，无失败工具或失败Agent轨迹。

## 尚未完成

- 赛事数据没有提供风险要素和证据片段人工金标准，因此仍不能正式计算80%风险抽取准确率和
  85%证据召回率；市场表现标签不能替代风险抽取金标准。项目不建设人工通读全文制作金标准
  的产品业务，人工环节仅复核机器已经定位的风险和证据。
- 旧版20家公司Agent特征试验已人工停止；旧产物只用于定位逐风险调用和全量裁决的成本问题，
  不作为新编排架构的效果结论。新架构尚未进行付费模型冒烟。
- 2025时间回放已经被开发过程查看，不能再充当最终未触碰盲测；需要隐藏测试集或重新封存
  样本做最终评估。
- 网页目前以单份文件分析为主，Chroma持久化已改为后台任务；尚缺少分析任务进程级持久化、
  服务重启后的人工确认恢复、断线重连、批量公司队列、权限和部署监控。
- 典型案例报告、统一API、比赛提交格式和数据到位后的自动评测流水线仍需完善。
