# 项目状态（截至 2026-07-20）

本文件用于回答三个问题：目前已经完成什么、未来还需要什么、下一步先做什么。准确率与
召回率必须在比赛数据和人工金标准到位后实测，当前不提前宣称达到赛题阈值。

## 已完成

### 数据与证据底座

- 已建立公司、文档版本、来源哈希、分析运行、证据、风险、Agent轨迹和人工审计的SQLite目录。
- 可解析带文字层或需OCR兜底的招股书PDF，保留物理页码、印刷页码、原文坐标和页面截图。
- 文档切片和向量索引按 `document_id/embedding_model` 隔离并缓存，可重复分析而不重复向量化。
- 网页支持拖入单份招股书，并自动识别股票代码、公司名称和招股书日期，识别结果允许校正。

### Agent风险分析

- 12类风险按职责分配给财务、法务、业务和市场Agent，覆盖现金消耗、客户/供应商集中、
  关联交易、赎回/对赌、诉讼处罚、牌照依赖、单一产品依赖等风险。
- 每个专业Agent会先用DeepSeek自主生成语义搜索问题，再通过DashScope向量索引寻找其负责
  风险的候选原文，并由该Agent完成证据约束分析。
- 固定查询、BM25和硬锚点不是主分析路径，只在搜索规划、向量服务或模型节点失败时兜底。
- 搜索规划、证据分析和最终裁决均支持指数退避重试；JSON格式、风险覆盖和证据白名单错误
  也会触发重试。
- 决策Agent只能引用专业Agent提交的提案与证据，可接受、调整或驳回并记录角色分歧。
- 所有风险结论必须引用实际候选 `chunk_id`；无证据时不生成正式风险结论。

### 页面、人机复核与交付

- Streamlit页面可展示PDF解析、各专业Agent搜索和分析、决策Agent裁决、证据报告生成的实时
  进度；模型结构化输出按角色卡片流式显示。
- 页面可查看结论、严重程度、置信度、PDF原文、页码、坐标、高亮截图、公式核验和Agent轨迹。
- 已支持人工确认、驳回、编辑、复核人及意见、历史审计记录和正式报告导出门禁。
- 人工复核结果可导出为版本化标注快照，后续可直接用于算法和大模型评测。
- 已具备单公司从PDF上传到待复核风险报告的完整原型闭环，命令行与网页共用同一业务服务。

## 尚未完成

- 比赛提供的3至5年招股书、公司基础信息、行情和表现标签尚未到位，因此尚无正式训练集、
  测试集、人工金标准，也不能计算80%风险抽取准确率和85%证据召回率。
- 当前以已定义的12类风险为主要职责边界，尚缺少“未知/非标风险发现Agent”对全文进行开放式
  扫描并提出风险字典之外的新风险。
- 尚未完成首日、5日、20日、60日表现标签生成、Point-in-Time特征、风险预测训练和回测，
  也未接入市场情绪共振评估。
- 网页目前以单份文件同步分析为主，尚缺少持久化后台任务、断线重连、批量公司队列、权限和
  部署监控。
- 典型案例报告、统一API、比赛提交格式和数据到位后的自动评测流水线仍需完善。

## 下一步

数据尚未到位时，下一项最有价值的工作是实现“全文开放式风险发现Agent”：分章节扫描整份
招股书，发现12类风险字典之外的非标风险，再交给现有专业Agent检索证据、交叉核验和决策。
同时建立可直接接入未来金标准的评测脚手架，预留风险类型准确率、证据片段召回率和首日/5日/
20日/60日业务指标。

数据到位后，应立即按时间切分数据并执行：资料登记与完整性检查 → 小批量人工金标准 →
抽取/证据评测 → 提示词与检索调优 → 行情标签与预测回测 → 批量生成测试集预测及案例报告。
