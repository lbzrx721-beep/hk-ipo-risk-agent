# 港股 IPO 多智能体风险预警系统

面向港股 IPO 招股书的证据级解析、多角色尽调、上市后风险预测与人机复核原型。

## 当前状态

第一阶段的可运行基线已经完成。当前可以使用一份公开招股书跑通：

```text
PDF -> 页面与坐标 -> OCR兜底 -> 表格/图片/流程图候选检测
    -> 有框/无框表格恢复表头、行列、单位、期间和单元格坐标
    -> 普通段落切片 + 表格专用语义切片
    -> DeepSeek风险发现Agent按章节包双路并行阅读原文
    -> qwen3-embedding在后台与风险扫描并行建库
    -> AI公司画像与风险适用性判断 -> 人工确认本次分析范围
    -> LangGraph并行调度财务/法务/业务/市场Agent生成语义搜索问题
    -> 向量召回补充证据/反证 -> Kimi四个专业角色各一次批量核验
    -> 普通结果确定性整合 -> 仅冲突/复杂重大项调用冲突升级模型
    -> Evidence -> RiskFinding/Calculation -> 高亮截图 -> 风险JSON
    -> Point-in-Time上市后表现预测 -> 人工确认/编辑/驳回
```

现有英矽智能历史基线已输出8条待人工复核风险，每条均包含PDF物理页码、
印刷页码、原文、坐标、证据截图和置信度。DeepSeek 默认按约70,000字符的章节包进行
全文风险发现，同一波并行扫描2个章节包；下一波继承前序主题记忆。四个专业角色并行，
每个角色使用独立ARK客户端，把全部已分派风险交给 Kimi 一次性核验；未配置 Kimi 时
自动复用主 LLM 路由。DeepSeek同样通过ARK调用，模型名保持 `deepseek-v4-flash`。
模型不能删除或最终驳回候选。
赛事2020—2025年565份招股书和411万条官方行情现已接入，首日/5日/20日/60日标签已经生成。
其中554家公司已生成34个严格Point-in-Time特征，并完成招股书结构、市场环境和融合三组
五日显著下跌基线。当前三组模型均未通过业务质量门槛，产物用于建立可复现评测底座，
不能作为已有效的正式预警模型；下一阶段必须批量加入Agent招股书风险特征。

候选风险现可通过命令行或 React + FastAPI 工作台执行确定性核验、人工确认/驳回/编辑和
最终报告导出。核验与人工决定均写入SQLite审计记录；任何失败核验都不能被标记为
`verified`。工作台支持拖入一份或多份招股说明书PDF，完成文件校验、幂等登记、解析、
开放风险发现、风险范围人工确认、多Agent批量分析、风险整合、报告生成并进入人工复核。

## 2026-07-24 Agent调用架构优化

- 风险发现采用约70,000字符章节包，普通招股书通常拆为6—12批；每轮并行扫描2批，
  下一轮共享之前已发现的主题记忆。正常流程不使用 `has_more` 反复续扫。
- PDF解析后，内存向量建库与DeepSeek全文扫描并行；向量化不占主进度，专业Agent
  检索证据和反证前才在汇合点等待索引就绪。
- 表格不再压扁为散文：PyMuPDF先解析网格表，无边框财务表通过文字坐标恢复多层表头；
  每张表保存规范化Markdown、逐行“表头=值”语义、单位/币种/期间以及单元格坐标。表格
  专用切片与普通段落一同进入 pgvector，并保留本地 `vectors.npy` 备份；专业Agent收到表格类型、表格ID及
  单元格引用，可按同一行和同一口径核验数字。
- 全部原始候选、合并血缘和证据映射继续保留；只合并同一底层事实和风险机制，单条合并风险
  最多保留8个互补证据片段。
- 专业Agent从“每条风险一次模型调用”改为“四个角色各一次Kimi批量调用”；证据和反证
  由混合检索提前备齐，不再触发专业模型续轮。
- 汇合节点改为风险整合器：普通专业支持项直接进入人工复核，只有分歧、冲突和复杂重大项
  调用模型；机器没有最终驳回权限。
- 单公司调用次数、输入/输出Token和估算人民币费用继续完整统计；默认不设累计硬门限，
  不再因为长文档输出较多而暂停分析。
- 流式业务卡片按已完成JSON对象增量生成并按风险编号稳定更新；后续快照解析失败时不会
  删除上一版有效卡片。隐藏Agent页签和原始JSON不再参与每次实时重绘。
- pgvector按 `document_id + embedding_model + chunk_id` 隔离公司与文档版本；本地
  `vectors.npy` 可用于迁移、恢复和离线复验，不参与正式在线检索。
- 每页本地检测图片对象、表格网格、文本列和流程图几何候选；视觉模型接口已预留，但不会把
  整本PDF逐页发送给视觉模型。
- 本轮75项相关回归测试、Ruff与mypy通过；尚未重新启动网页进行付费模型端到端实测。

## 2026-07-19 混合检索与DeepSeek证据分析

- 新增真实语义向量检索，使用OpenAI兼容Embedding接口批量生成向量并按余弦相似度召回。
- 使用倒数排名融合（RRF）合并BM25与语义候选，审计记录保留两路分数和排名。
- 文档向量按来源哈希、切片文本、模型和维度生成指纹，缓存到文档级模型目录；相同版本
  再次分析不会重复向量化。
- DeepSeek通过JSON Output返回结构化判断，只能引用本次提供的候选 `chunk_id`；未知证据、
  重复证据、超出规则数量或不完整结构会被拒绝。
- Embedding批次和DeepSeek证据分析节点均支持指数退避重试；DeepSeek的JSON解析与证据
  白名单校验也属于同一重试节点。重试耗尽后才回退到满足全部锚定关键词的BM25规则证据。
- `AgentTrace` 记录实际尝试次数、重试次数、检索/分析模式与最终降级原因。
- 已完成真实百炼1024维向量连接、真实DeepSeek V4 Flash JSON连接，以及公开招股书现金流
  证据的受约束分析验证。
- 全量74项测试、Ruff和mypy通过。

默认重试参数位于 `configs/base.yaml` 的 `agents` 区段：首次失败后等待1秒、2秒，单次
等待上限8秒，`max_retries: 2` 表示首次调用之外最多再重试2次。普通鉴权或参数类4xx错误
不会重复请求；连接、超时、429、服务端错误及可重新生成修复的模型JSON/证据校验错误会重试。

## 2026-07-20 多角色分析与证据裁决

- 风险规则按 `owner` 分发给财务、法务、业务和市场 Agent，共享同一文档检索索引，避免
  重复向量化。
- 每条规则支持主查询和多组 `query_variants`；向量不可用时，多查询BM25仍会把宽召回候选
  交给DeepSeek，`required_keywords`只用于模型失败后的高确定性规则兜底。
- 已启用关联交易、赎回/对赌、诉讼处罚和单一产品依赖等非标风险，目前风险字典覆盖12类。
- DeepSeek决策Agent只能引用专业Agent已选中的提案ID和证据ID；它可以接受、调整或驳回，
  严重程度分歧和“是否成立”分歧均会写入裁决工具调用。
- 决策节点与证据分析节点使用相同的指数退避重试策略；裁决重试耗尽后使用证据约束的
  确定性裁决，不会丢失已完成的专业Agent结果。
- `risk_analysis.json` 保存总控、专业角色和决策节点的父子 `AgentTrace`。Streamlit复核页新增
  “Agent轨迹”页签，可查看角色分工、输入输出、模型模式、尝试次数、降级原因和冲突处理。
- 这些改进建立了可评测链路，但在比赛数据及人工金标准到位前，不能宣称已经达到80%准确率
  或85%证据召回率。

## 2026-07-20 Agent自主证据检索

- 财务、法务、业务和市场Agent不再以固定关键词查询作为主检索入口；每个Agent先根据自己的
  风险职责、风险定义和证据字段，自主生成3至6个互补语义问题。
- Agent生成的问题直接查询同一份招股书的智谱向量索引，召回原文切片后再由该角色的
  DeepSeek证据分析节点判断风险是否成立；固定查询与BM25仅作为故障兜底。
- 搜索规划、JSON结构校验和风险覆盖校验使用与其他模型节点一致的指数退避重试策略。
- `AgentTrace` 新增 `agent_search_planning` 工具调用，记录角色、风险类型、实际问题、模型、
  提示词版本、尝试次数及兜底原因，实现搜索到裁决的完整可追踪。
- Streamlit运行台会实时显示每个Agent的搜索规划流、检索阶段、分析流和完成状态；发生兜底
  时会显示“检索兜底”，不会把算法结果伪装成模型检索结果。
- 当前能力、交付边界和后续工作统一维护在 `docs/项目状态.md`。

## 2026-07-22 全文开放式风险发现

- 新增风险发现Agent，按字符预算分批扫描整份招股书，寻找固定12类风险之外的公司特异性风险。
- 模型只能引用当前批次真实 `chunk_id`；未知证据ID会使该批次失败并按统一重试策略重试，
  重试耗尽后只降级该批次，不中断固定风险分析。
- 批次发现完成后，DeepSeek会再次从全文视角执行全局语义合并，识别标题不同但实质相同的
  风险；每条原始候选必须且只能映射到一个合并结果。
- 人工范围确认前不再按固定数量截断候选。全局合并失败时只启用精确标题兜底，并保留全部
  候选、错误和映射记录。
- 开放风险会按职责交给财务、法律、业务或市场Agent重新检索与核验，随后再由决策Agent裁决；
  风险发现Agent本身不能绕过证据白名单直接生成报告结论。
- 开放风险执行严格关闭：专业证据模型或决策模型未成功时，不启用关键词分析或确定性裁决
  自动接受；固定12类风险仍保留原有故障兜底。
- Streamlit运行台新增风险发现Agent卡片，实时展示批次进度和模型流式输出，并在失败时明确显示
  已降级状态。完整发现、专业复核、决策和工具调用均写入父子AgentTrace。

- 数据按 `document_id + embedding_model + chunk_id` 隔离；只有数据库声明完成、切片数量一致且
  向量维度正确时才允许复用，避免半份文档进入检索。
- 写入按公司使用独立事务和二进制COPY，支持受控并发、失败回滚、断点续传及幂等重跑。
- 当前RAG始终先限定单一 `document_id`，再对该公司约数千个切片做精确余弦排序；这样不会让
  其他公司的向量互相干扰，也不依赖全局HNSW近似召回。跨公司检索将来需要时再单独建HNSW。
- 正式分析只支持 pgvector；NumPy文件仅作为本地向量备份和数据库迁移来源。
- 数据库连接只从系统环境变量或项目根目录被忽略的 `.env` 读取；仓库只提供
  `.env.example`，不提交真实密码。

初始化、迁移和验收：

```powershell
conda activate hk-ipo-risk
python scripts/init_pgvector.py
python scripts/import_embeddings_to_pgvector.py --workers 8
python scripts/import_embeddings_to_pgvector.py --verify-only --workers 8
python scripts/verify_pgvector_retrieval.py --company-id 02263
```

## 2026-07-23 Point-in-Time预测基线

- 从1.1GB赛事全市场行情生成可复用的每日市场情绪缓存；每家公司只读取招股书发布日期之前
  的5/20/60个交易日，提取市场收益、上涨比例、波动、振幅、成交趋势和活跃证券数。
- 基于此前已经能够观察到的IPO样本，生成30/90日IPO数量、最近五日表现和显著下跌率；任何
  标签的 `observation_date` 晚于当前预测时点时都会被排除。
- 为554家具有完整五日标签的公司生成34个特征和逐特征
  `available_at/source_ref` 审计记录；上市日期、上市后公司行情和首日昨收价发行价代理均不
  进入特征。
- 训练招股书结构、市场环境和融合三组逻辑回归消融基线。预处理只在2020—2023训练集拟合，
  阈值只在2024验证集选择，并限制验证集预警覆盖率不超过50%；2025只作时间回放。
- 输出PR-AUC、ROC-AUC、召回率、精确率、Brier、校准分箱、Top-20%命中、逐公司概率和线性
  贡献解释。融合模型2024验证PR-AUC为0.3089，低于当年正例率0.3425，业务质量门禁未通过；
  因此当前结果只证明流程可运行，不证明预测具有业务有效性。

## 核心原则

- 每条风险结论必须绑定原文、PDF 页码和坐标。
- 数值结论必须保留输入、单位、期间和公式。
- Agent 只通过结构化对象协作，不靠自由聊天传递关键事实。
- 预测特征必须满足 Point-in-Time 约束，禁止使用上市后信息。
- 原始数据只读，中间数据可重建，最终产物可追溯。

## 核验、人工复核与最终报告

列出一个分析任务的全部候选风险：

```powershell
python scripts/review_findings.py list `
  --run-id "RUN-03696-..." `
  --project-root "D:\东吴证券"
```

先执行不改变状态的确定性核验，再由投研人员作出决定：

```powershell
python scripts/review_findings.py verify `
  --run-id "RUN-03696-..." `
  --finding-id "F-03696-0001" `
  --project-root "D:\东吴证券"

python scripts/review_findings.py review `
  --run-id "RUN-03696-..." `
  --finding-id "F-03696-0001" `
  --decision confirmed `
  --reviewer "投研复核人" `
  --comment "原文、期间和风险表述一致" `
  --project-root "D:\东吴证券"
```

`rejected` 和 `edited` 必须填写复核意见；`edited` 还必须通过

## Web分析与人工复核工作台

首次使用或前端代码更新后先构建 React 前端：

```powershell
conda activate hk-ipo-risk
Set-Location frontend
npm install
npm run build
Set-Location ..
python scripts/run_web_api.py
```

服务就绪后默认打开 `http://127.0.0.1:8000`。不希望自动打开浏览器时使用
`python scripts/run_web_api.py --no-browser`；开发热重载使用
`python scripts/run_web_api.py --reload`。

开发阶段需要自动检查页面时，使用项目内的浏览器测试入口。它会使用
`tmp/npm-cache-playwright`，避免Windows全局npm缓存权限异常导致启动超时：

```powershell
.\scripts\playwright_cli.ps1 --version
```

页面默认进入“新建分析”：拖入一份或多份PDF后自动识别股票代码、公司名称和招股书日期，
必要时可在页面校正识别结果，再建立统一的公司分析队列。上传一份时自然按单公司运行，
不再维护独立的“单份分析”模式。
系统会按阶段显示PDF解析页数与切片数、专业Agent运行、决策Agent裁决和证据报告生成进度；
分析任务在后台继续运行，切换页面后返回仍会恢复同一任务的实时事件和Agent输出。三个工作区
使用独立路由 `/analysis`、`/results` 和 `/review`，根路径 `/` 同样进入新建分析；
三个工作区共享同一个服务地址和浏览器会话。
风险发现完成后，页面会停在“确认本次分析范围”：页面先解释从批次原始发现到全局语义合并、
目录兜底和业务适用性筛选的完整漏斗，再允许筛选候选风险、调整负责Agent与严重度、补充分析
要求或新增风险。点击“确认范围并启动专业Agent”后，四个专业Agent才会并行执行。
完成后可以直接点击“进入人工复核”。同一公司同一PDF通过SHA-256识别，只登记一次且不会
重复复制原始文件；不同内容或不同日期会生成独立的不可变文档版本。

“新建分析”页面使用统一入口：既可拖入一份或多份新的招股书PDF，也可从赛事数据集中按
train/validation/test分组选择公司。上传后系统逐份识别股票代码、
公司名称和招股书日期，允许修正后建立队列；文件登记与分析在后台执行，页面会立即进入队列
控制台。可滚动队列显示每家公司的等待、分析中、已完成、失败或已暂停状态，选中的公司在
同一页面展示实时进度、事件和报告入口。队列支持在当前运行公司完成后安全暂停、继续和重试失败
公司，不影响现有文档与运行之间的隔离设计。单个上传文件上限250MB，损坏、空白、无页面或
带密码的PDF会在分析前拒绝。

批量队列会先并行预处理最多5份PDF：解析页面、构建表格/文本切片并生成文档向量缓存；
每家公司会明确显示“预处理中”。预处理进入安全缓存后，DeepSeek/Kimi Agent按受控公司并发
启动，默认同时推进2家公司；每家公司内部的专业Agent仍由LangGraph并行。任意公司的风险发现
完成后都会立即进入独立的候选风险人工确认节点，不等待整个批次。正式分析直接复用解析和
向量缓存，不会再次处理同一版本。
向量模型的批次大小、请求并发、文档并发、超时和重试均在
`configs/providers.local.yaml` 的 `embedding` 区段独立配置。

页面支持选择分析任务、查看复核进度、风险结论、严重程度、置信度、PDF原文、物理页码、
印刷页码、坐标、高亮截图、公式、全部确定性核验项和多Agent推理轨迹。轨迹页会展示每个
角色的工具调用、模型模式、重试降级与裁决分歧。填写复核人及意见后，可以确认、驳回或编辑
风险；操作会调用与命令行相同的 `ReviewService`，并写入SQLite不可变审计记录。

系统不建设“人工通读全文并制作风险金标准”的业务。全部风险复核完成后，“导出正式报告”
按钮才会启用。

## 模型供应商固定分工

- 智谱 BigModel 的 `embedding-3-pro` 只负责招股书向量化和语义检索。
- DeepSeek 的 `deepseek-v4-flash` 负责全文开放式风险发现，财务、法务、业务、市场Agent的
  语义问题规划和候选原文分析，以及决策Agent的冲突查证与最终裁决。
- 程序不读取 Windows 用户环境变量中的密钥，固定读取
  `configs/providers.local.yaml`。该文件在本机保存真实密钥，并被 `.gitignore`
  排除；字段示例见 `configs/providers.example.yaml`。
